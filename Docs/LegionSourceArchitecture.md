# Legion C++ source architecture

Current game flow: Hall -> Campaign contract -> Legion battle -> Campaign result. The turn-based Battle, Run and WFC code remains a separate gameplay path.

- Campaign owns contracts, roster, rewards and persistence. Legion reads a contract at deployment and reports a result; tactical actor state is world-local.
- Legion/Terrain now owns the terrain grid and its path queries. LegionTerrainGrid.cpp samples world terrain and provides read-only terrain/cover data and the existing map rasterizer. LegionTerrainPathfinding.cpp uses grid data only, with no actor or HUD dependencies. FindPath keeps its direct-line shortcut, weighted A*, smoothing and fallback contract.
- Legion/Deployment owns StartPlay orchestration: zone, weather and terrain, forest, map textures, initial roster, then commander placement. GameMode retains the deployment gate, Tick, reinforcement scheduling and result reporting. Initial and delayed brigades share one spawn implementation.
- Legion/Debug owns the GameMode's screenshot and self-test implementations. Runtime calls, flags and Unreal class identity stay in place.
- Experimental/LegionBattle still hosts the reflected unit actor header plus lifecycle, controls, HUD, deployment and weather. `ALegionUnit` keeps that public source location for reflection and asset compatibility; implementation is split by responsibility: `LegionUnit.cpp` (actor lifecycle/formation rebuild/tick orchestration), `Legion/Units/LegionUnitOrders.cpp` (commands and directives), `LegionUnitSimulation.cpp` (soldier micro-state and world-space kinematics), `LegionUnitRepresentation.cpp` (skeletal component writes, animation driving and HISM transforms), and `LegionUnitCombat.cpp` (damage, hits and death). `Legion/Units/LegionUnitInternal.h` is private implementation sharing, not a reflected type home. Experimental/AITacticalCommand is an adapter, not an owner of battle state. The source paths are not a reason to change reflected class names or assets.
- Soldier simulation no longer writes representation components inline. `UpdateSoldiersMicroAI` updates authoritative soldier state/kinematics; skeletal component transforms, gun recoil and blend-space driving are written afterwards by `WriteSkeletalSoldierRepresentation`, while instanced matrices remain centralized in `WriteAllSoldierTransforms`. Keep the existing tick order as the compatibility boundary.

## Migration order

1. Done: separate soldier simulation from representation writes using the existing tick order as the compatibility boundary.
2. Profile transform computation, instance updates and render-state invalidation separately before changing the instanced path. In UE 5.8, the HISM batch-transform wrapper still calls `UpdateInstanceTransform` for every instance; changing the call site alone does not eliminate that work.
3. Revisit spatial indexing only if a representative larger battle shows local queries dominating. Keep legacy gameplay and campaign persistence out of these changes.

## CPU profiling

The `ER_Legion_` CPU trace scopes distinguish deployment and map baking, GameMode tick and active projectile simulation, soldier micro-AI, and representation writes. `FriendlyFireLine`, `StepOffset` and `LocalAvoidance` remain nested in `MicroAI`; do not add their times to the inclusive micro-AI total. `SkeletalRepresentation` now owns skeletal component writes, gun recoil and `AnimationDrive`; it is a sibling of `MicroAI`, so do not interpret the split itself as a micro-AI speedup when comparing older traces. `AnimationDrive` measures the game-code animation driver, not engine pose evaluation. `InstancedTransforms` measures writes for the instanced representation. NullRHI timing is for CPU investigation, not rendered frame rate.

Use `Lvl_Legion` with `-game -nullrhi -trace=cpu -tracefile=<path> -LegionSeed=20261 -LegionZone=0` and a separate `-UserDir=<path>` to avoid touching campaign saves. For the 128-soldier patrol case use `-NoDeployScreen -seconds=8`; for the 384-soldier instanced engagement use `-LegionLegions=4 -LegionSoldiers=48 -LegionCloseup -seconds=27`. These exercise different representations and are not a before/after benchmark. Inspect complete GameMode tick intervals in Insights; for combat start at the first active `ER_Legion_Bullets` tick. A cold user directory can make the editor executable wait for a synchronous asset-registry scan after deployment and before the first battle tick; exclude that wait from per-tick results.

## Skeletal soldier performance harness (2026-12)

`-LegionPerf` is the rendered frame-time benchmark: it orders a player all-out assault, moves the camera to the worst-case overhead view (all soldiers visible), then samples real frame times for 10 s of peak combat and logs `[LegionPerf]` lines: mean/p50/p95/max, thread breakdown (when run with `-ExecCmds="stat unit"`), and manual game-code timings (`Legion/LegionPerf.h` accumulators: microAI / skelRep / bullets / unitTick / gameModeTick per frame). `-LegionForceSkeletal` overrides `MaxAnimatedSoldiersPerSide` so the ladder can force skeletal representation at any soldier count. Standard run: `-game -windowed -ResX=1920 -ResY=1080 -ForceRes -LegionPerf -LegionForceSkeletal -LegionSoldiers=N -LegionSeed=20261 -LegionZone=0 -seconds=30 -ExecCmds="stat unit" -log`. Diagnostic flags: `-nullrhi` (game-thread-only floor), `-LegionNoHitProxy` (drop physics hit capsules; player shooting then cannot hit, battle sim unaffected), `-LegionGunCullDist=cm` (0 disables distance-based gun hiding), `-LegionNoURO`.

Reference measurements on the dev machine (overhead worst case, before the stationary-write optimization): scene baseline (8 soldiers total) already renders at ~17.5 ms frame / 16.8 ms GPU from terrain+grass+forest alone; at ~355 skeletal soldiers the **game thread dominates at ~33.7 ms** of which only ~5 ms is Legion game code — the rest is engine per-skeletal-component machinery (bone finalization/upload, transform cascades, component tick dispatch) that URO cannot skip. Physics hit capsules cost ~3.5 ms/frame at 375 soldiers even in `-nullrhi`. Implication: per-soldier skeletal components have a structural per-frame engine tax; the scale ceiling comes from that tax, and ISKM is the only architecture that removes it.
